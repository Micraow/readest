# Linux 便携包恢复与验收

本流程从既有 CI 成品和固定 CEF 运行库恢复便携目录，不重新编译应用。
先按 [构建说明](academic-linux-build.md) 校验所有下载分片及完整归档，
只使用来源完整性验证通过的候选。不要把用户论文、截图、账号配置或签名密钥加入发布包。

## 组装

准备两个本地目录：
- native：包含原始 `readest`、`provenance.json`、`LICENSE`
- cef：按 CI 的 `prepare-cef` 步骤得到的固定 CEF 目录

运行：

```sh
python3 scripts/package-academic-linux.py \
  --native /path/to/native --cef /path/to/cef \
  --output /path/to/Readest-Academic-Linux-x86_64
```

输出目录必须尚不存在。脚本先验证 CI 的源码完整性标志、原始 ELF 哈希和每项 CEF
运行库哈希；只对副本运行 `strip --strip-unneeded`。随后逐项比较已分配 ELF 节、
程序头和 PT_LOAD 加载字节，仅允许 ELF 头的节表位置/数量元数据变化。
验证记录保存在包内 `package-verification.json`。相对路径启动器 `Readest`
不增加调试端口、沙箱参数、系统安装或权限修改。

脚本已经使用 academic-13 的真实 CI 输入完整重跑，去符号后两项输出与已交付包一致。
它只恢复目录，不代表已完成 GUI 验收。原始构建证明中“验收待完成”的字段保留原样；
新的验收结果需另记录日期、平台和准确范围，不能把构建成功当作显示正确。

## 打包前检查

1. 在目录中加入中文使用说明，说明平台依赖、来源提交、测试范围和已知限制
2. 确认 `LICENSE`、CEF 的 `LICENSE.txt`、`CEF_LICENSE.txt`、`CREDITS.html` 均保留
3. 用本包 `LD_LIBRARY_PATH` 检查 `ldd readest`，不应出现缺失库
4. 对最终所有普通文件生成 `SHA256SUMS`，校验后再压缩
5. 重新读取压缩包，核验所有成员哈希、相对路径及两个启动文件的执行权限
6. 在独立测试配置中启动此目录的原生程序；不把测试配置放入压缩包
7. 保存包、包外 SHA-256 和验收截图后再宣布交付

## 最小实屏回归

- 双栏正文和跨页续段完整，作者说明/脚注不插入句中
- 公式与前后正文的边界清楚，行内分式顺序不变
- 并排图、共享图例、双图注和算法末行完整
- 引用/脚注唯一跳转、返回、改变字号后返回及关闭图像放大后的落点
- 浅/深色数学样式；自动模式与真实系统主题事件分别记录
- 窄窗长 URL 折行、改字号和改窗口宽度后的阅读位置

只记录实际观察到的结果。没有可操作的系统深浅色切换入口时，把动态系统事件标为未验证。
发布新包不应覆盖或撤下已验收的旧包，直到新包的必要验收通过。
