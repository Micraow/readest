# A small local relationship model for source-preserving reflow

The most promising product hypothesis is to preserve source glyphs and painted objects, reuse mature word wrapping, and learn the relations that make those objects safe to rearrange. The model should predict roles, paragraph continuity, reading-order constraints, formula-number and caption ownership, and uncertainty. It need not regenerate prose or reconstruct full LaTeX. Full formula semantics become necessary only when attempting internal mathematical transformation; a readable protected formula needs reliable atomic boundaries, anchors and scale instead.

## Evidence for size, and what is still missing

Google Research's ICDAR 2023 sparse-graph reading-order paper reports 267K parameters, including a 144K MobileNetV3-Small image branch. Geometry-only F1 was 0.802 for reading-pattern classification and 0.891 for paragraph clustering; edge-image features raised these to 0.819 and 0.902. Training used Google Cloud Vision OCR, private annotated images, PubLayNet and 10M steps. Its approximately 1.07 MB FP32 weight size is arithmetic from parameter count, not measured runtime RAM. We found no official released trained component to plug in. The paper explicitly identifies failures involving adjacent sections and table structure. This supports the architecture, not scientific-math fidelity. [Primary paper, sections 3.5 and 4](https://arxiv.org/pdf/2305.02577)

GLAM reports a 4M-parameter graph approach based on electronic-PDF metadata. Its task is document layout analysis, so it is additional evidence that native geometry is useful, not a formula-ownership result. [Primary paper](https://arxiv.org/abs/2308.02051)

Our one frozen 25-parameter probe demonstrates that learned geometry can improve one synthetic association task at very low cost. It still made confident cross-column mistakes and relied on perfect candidate boxes. The two radical-tip pixels in the earlier real-paper experiment are a different defect: logical glyph bounds did not cover actual text-paint extent. A relationship model cannot repair pixels clipped by its renderer. Pixel provenance and semantic association need independent verification.

## One preferred architecture, with bounded alternatives

Start with a small edge scorer over source-derived glyph/line/block candidates. Features should include normalized geometry, font/baseline signals, candidate type confidence, separators, nearby competing parents and column context. Keep every input source ID immutable. Predict typed relations, then enforce ownership, acyclic order and supported parent-position constraints. A contradiction or missing source provenance must refuse the affected parent at its supported position; if no safe order exists, keep the page original and count a failure.

A linear classifier provides a cheap floor. The next justified capacity increase would be a sparse graph or short local sequence encoder with roughly 0.1–0.5M parameters, not a text-generating model. Those are design targets, not measured performance. Four-byte weights alone would be roughly 0.4–2 MB; activations, runtime and PDF rendering need separate measurements. Sparse graph context is preferable when arbitrary source extraction order would contaminate a sequence model. A sequence model is useful only after reliable local chains exist.

A small visual branch should be added only when errors demonstrate missing separators, brackets, rules or image context. It should inspect candidate-pair surroundings, not generate replacement text. Teacher distillation is optional later: teacher relation scores on licensed data plus verified labels can supervise a student, but independent gold labels must detect inherited teacher errors. No paid/closed API or VLM is required by this proposal. [Original distillation paper](https://arxiv.org/abs/1503.02531)

Native and scanned PDFs are different input regimes. Native PDFs offer stable glyph IDs, font metadata and paint operations, although logical bounds and extraction order are not semantic truth. Scans offer pixels; detection/OCR or fragment segmentation is needed before analogous relations can be formed. OCR uncertainty and lost glyph identity must be reported separately. A native-PDF result must never be presented as a scan result.

## Data and rights

GraphDoc is the most relevant real relation dataset found: 80,863 pages, 4,138,423 triplets, with parent/child/reference/sequence relations. Its official release says page images and enhanced JSON derive from DocLayNet and remain subject to CDLA-Permissive-1.0; the repository's MIT code license is not the dataset license. Model/training/evaluation code is still announced as forthcoming. Relations are rule-derived with human verification. The schema is useful for captions, hierarchy and reading order, but does not provide explicit formula-number or painted-glyph ownership truth. [Official release](https://github.com/yufanchen96/GraphDoc), [annotation methodology](https://arxiv.org/pdf/2502.02501)

DocLayNet supplies matching single-page PDFs and text-cell JSON as additional assets. Its full core and extras are 28 GiB and 7.5 GiB, outside this quick-experiment disk budget. A later bounded subset must preserve document identity and source provenance. [Official assets and license](https://github.com/DS4SD/DocLayNet)

Original synthetic source trees provide unambiguous authored links and can vary geometry without importing paper content. For real source TeX, admit only individually verified reuse licenses such as CC BY or CC0 and preserve attribution, version, license URL and asset provenance. Publicly downloadable arXiv files are not blanket training or redistribution permission; the default arXiv license grants no further reuse rights by itself. [Official arXiv reuse guidance](https://info.arxiv.org/help/license/reuse.html)

Do not start with ReadingBank while its official README combines Apache-2.0 language with research-only/no-redistribution restrictions. Resolve that conflict first rather than treating the top-level license as sufficient. [Official README](https://github.com/doc-analysis/ReadingBank)

## Proposed next data gate, before training a larger model

Build a small rights-checked real corpus and annotation specification before choosing a neural architecture. A practical pilot is 60 documents and about 240 selected pages, split at document/template/source-collection level into 24 training, 12 calibration and 24 locked test documents. These counts are a proposed sampling plan, not completed data collection. All pages/versions from the same paper, source TeX template family and near-duplicate publication must stay in one partition. Related translated versions must stay together. The current ten diagnostic pages are regression-only and excluded from test claims.

Sampling quotas should cover English and Chinese/mixed text, dense mathematics/matrices, ordinary single-column prose, double-column float/footnote layouts, tables with merged cells, and native versus scanned input. Include at least four long documents with several contiguous pages and page-crossing paragraphs, rather than selecting only easy isolated pages. Report each slice and full-document failures separately; a small pilot cannot certify every intersection of this matrix.

Annotate immutable source candidates, true object extents, formula-number and caption links, direct paragraph successors, heading scope and allowed line-break boundaries. Mark ambiguous source order explicitly. Record detection omissions and unknown parents instead of annotating only successfully detected boxes. Have a second annotator review all test-page critical relations and a sample of training labels, with adjudication of disagreements. If annotation averages 10–20 minutes per page, 240 pages imply roughly 40–80 person-hours before double review; this is a planning estimate, not measured labor. Begin with 12 pages to measure the actual cost and refine the labeling instructions before freezing the larger test set.

No 35+GiB corpus download, GPU purchase or paid teacher run is justified by the current result. A features-only pilot with <=100K candidate pairs and 48 FP32 features needs about 19.2 MB for the contiguous feature matrix; Python objects and training overhead add more. The measured tiny run fits the current one-CPU/1-GiB budget. A graph/visual training budget remains unmeasured: profile a small fixed batch first and report evidence before requesting more resources. The quick cloud budget is not a statement about all eventual user devices.

## Acceptance and falsification

1. Geometry gate: preserve painted source objects through transforms, clipping and raster envelopes; distinguish native logical bounds from actual paint extent. Test ordinary text, radicals, accents, negative bearings, rotations and clipping with original generated fixtures. No learned model can override failed source coverage.
2. Candidate gate: measure role/parent candidate recall against all authored or audited objects, including misses. Report oracle-candidate and real-candidate results side by side.
3. Relation gate: wrong-owner rate among accepted links, recall over all true links, paragraph successor F1, exact page-order success and cross-page continuity. Calibrate rejection only on calibration documents; report confidence intervals and per-source worst cases. Confident cross-column mistakes are critical failures even when aggregate F1 looks high.
4. Reflow gate: compare against unchanged k2 on the same source raster, output width and target text size. Count complete prose genuinely rewrapped at readable size, omissions, duplicates, protected objects and full-page fallbacks. Original-image fallback stays in every denominator. Pixel coverage, color, equation/number association and table geometry are separate checks.
5. Device gate: cold start, per-page p50/p95, long-document peak RSS, model/runtime/package size, battery/thermal behavior on an actual representative Android device. The current 0.35 ms oracle-geometry score is not an end-to-end mobile latency.

Reject this model approach if it cannot beat a strong frozen geometry/column baseline on unseen real document sources at comparable accepted-error risk, if useful reflow coverage collapses under conservative refusal, or if candidate/paint errors dominate and learning adds no benefit. The next useful experiment is a small real-candidate and column-context relation evaluation after the geometry invariant is sound. Do not react to this one synthetic success by repeatedly enlarging models.
