# Local canvas cost probe

The earlier batch renderer allocated/filled an internal full-page bitmap for every local word/object. Change only the bitmap viewport: use a padded local canvas while preserving global PDFium device coordinates (`start_x=-local_left`, `start_y=-local_top`, original full page output size). No source mask is scaled, no native glyph is replaced, and paint order/shared-text action masks stay unchanged.

Gate: every output's source-support RGB comparison remains exact, and output coverage/geometry/content agrees with the old full-internal-canvas renderer on an original control and seen-page diagnosis. PDFium can alter tight-clip rasterization, so a local canvas is not assumed equivalent. Retain any differences; never waive source checks to claim speed. Sampling is still 2x here, not a fix for high-DPR undersampling. Cold native-step timings and complete-page timings are different measures.

First seen-page probe: all coordinates/sizes matched but the figure differed in 217 RGB pixels, max channel delta 1. That failed probe is retained. A generic retry on source-support difference recovered exact old bytes, but a stronger completeness issue remains: nontext support generated from the same local render cannot detect paint that the local clip omitted. Therefore the guarded candidate allows local canvases only for text-only units with independently preserved native-alpha masks. Every unit with nontext paint stays on the original full-internal-canvas path, without trying the local shortcut. Text source-support difference triggers original-path retry and a trace; neither path may waive unresolved source differences. This policy is primitive-based, not a graphic ID exception.
