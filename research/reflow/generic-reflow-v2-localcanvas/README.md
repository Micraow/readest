# Native local-text canvas, with unchanged paint fallback

This is a switchable rendering-cost candidate, separate from reading order and from the immutable full-internal-canvas renderer. No source PNG is resized and no glyph is redrawn through Unicode. Text-only units reuse independently measured alpha support. PDFium renders on a padded local bitmap with original global device coordinates. Any source-support difference retries the original full-internal-canvas path and remains a reported failure if still unequal.

**All units containing nontext paint stay on the original full-internal-canvas renderer.** The first unrestricted local-canvas probe failed on a graphic: 217 RGB pixels differed, max delta 1, although all 707 unit boxes/sizes matched. That failed result is retained. More importantly, support generated by the same clipped render cannot detect omitted nontext paint. Restricting the shortcut to text with independent masks avoids falsely treating selected-support equality as a coverage proof. The rule is primitive-based, not a page/graphic identifier exception.

## Paired native-step evidence

Sequential A-B-B-A, same existing plan/masks, same one-CPU affinity and interpreter. Every process was fresh, OS file cache was not flushed; shared-machine load was recorded. The original source PDF remained local.

- D4 original cold-step wall 6.247 / 12.491s, CPU 6.088 / 11.906s.
- D4 guarded local-text step wall 3.511 / 4.225s, CPU 3.456 / 4.092s.
- All 707 PNG file bytes and asset coordinates matched the first original run in both candidate runs and the repeated original run. No source-support failure.
- Original authored control: all 39 PNGs/coordinates also matched in A-B-B-A; no source-support failure. Its tiny step had substantial startup/measurement variability; do not infer large speedup from it.

These are existing-plan native-render steps, not page latencies. The original renderer's own timing changed substantially within the pair; no isolated-hardware or universal speedup claim is made.

## Complete cold page probe

The candidate plus the separate main-prose/float relation layer completed one fresh offline PP-S and native pipeline in **36.344s wall / 35.439s CPU**, one allowed CPU, **845.637MiB sampled family peak**. Model child startup/inference/exit, extraction, all closures, source replay, native assets, both initial and relation-adjusted HTML/audit writes were included. The final relation-adjusted output had 707 units, 7 paragraphs, 3 protected blocks and one cross-column relation. Full original-position replay and local source support matched at the tested grid.

Final HTML and all 642 referenced image bytes were exactly equal to the already fully inspected cross-column-flow preview. No extra rendering was needed to pretend there was another independent visual test. The output still has the prior preview's resolution, selection, spacing and interaction limitations.

The earlier same-flow/full-internal-canvas cold run **failed at 60.044s**, and an earlier tree-only run completed in 52.669s. System load and almost every phase differed. Do not attribute the entire 60→36s change to the canvas shortcut or claim stable worst-case performance. Terminal CPU includes waited model children; sampled CPU of currently alive processes does not. All versions/failures are retained.

Excluded from complete-page cost: downloads/install, browser load/paint, native rerender for target font size/DPR, selection, zoom, and real Readest platform integration. Thus the full interactive page budget and paper acceptance still fail or remain untested. This change does not address low-resolution CSS upscale; it makes a target-grid experiment more affordable but is not that experiment.

No new CI, private-content upload to public services, or holdout opening. Public results are aggregate numbers, source code and configuration only.
